## 0. Ідея: паралельність купується контрактом, а не worktree

Наївно B-11 → B-12 послідовні: збирач валідує позиції й порівнює `time_utc`, а це робота
перетворювача. Залежність знімається **одним рішенням, яке й так вимагає FSD**: `shared/`
не має права імпортувати `entities/`, тож збирач у `shared/api/aisstream/` **не може**
кликати перетворювач напряму — він отримує його **параметром**, так само як уже отримує
`connect` і таймер. Тоді збирачу потрібна лише **сигнатура** перетворювача, не код.

Так само B-13 потрібна лише **форма відповіді** `/api/snapshot`, а вона дослівно
зафіксована в `SPRINT-02.md:29`.

Отже: фаза 0 комітить у `main` два типи-контракти → три смуги стартують від цього коміту
одночасно й не торкаються спільних файлів → фаза 2 з'єднує їх одним рядком.

```ts
/** Мінімум, який збирачу треба знати про елемент: ключ і час для «найновіша на id». */
export type Collectable = { readonly id: string; readonly timestamp: string };

export type CollectOptions<T extends Collectable> = {
  connect: Connect;
  apiKey: string;
  windowMs: number;
  limit: number;
  /**
   * Перетворювач — ПАРАМЕТР: shared/ не імпортує entities/. `null` — «не валідна
   * позиція», включно з SubscriptionConfirmation; збирач такі мовчки пропускає.
   */

  now: () => number;
  setTimer: (fn: () => void, ms: number) => TimerId;
  clearTimer: (id: TimerId) => void;
  signal?: AbortSignal;
};

export type CollectResult<T> =
  | { kind: 'done'; items: T[]; reason: 'window_elapsed' | 'limit_reached'; finishedAt: number }
  | { kind: 'error'; code: ReadErrorCode; finishedAt: number };
```
