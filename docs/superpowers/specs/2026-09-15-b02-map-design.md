# B-02. Карта району — проєктне рішення

Дата: 2026-09-15
Завдання: `docs/tasks/SPRINT-01.md:28` (B-02), історія US-01 з `docs/tasks/PROJECT_BRIEF.md:45`
Статус: погоджено усно, чекає на реалізацію

## 1. Що треба зробити

З тексту завдання дослівно: Leaflet тільки на клієнті, шар OSM з атрибуцією, район і початковий вид з конфігурації, карта на всю доступну область.

Критерій приймання, теж дослівно:

1. пряме відкриття й оновлення сторінки працюють;
2. зміна розміру вікна перемальовує карту без артефактів;
3. `next build` проходить.

US-01 додає до цього те, що вже випливає з критерію: карту можна рухати й наближати, і на карті видно, звідки взята сама карта і хто її автори.

## 2. Стан репозиторію на момент рішення

B-01 залишив плаский каркас: `app/layout.tsx`, `app/page.tsx` із заглушкою, `tsconfig.json` зі `strict` і виключеним `reference`, `next.config.ts` з `agentRules: false`, `package.json` із точними (без `^`) версіями `next 16.3.5`, `react 19.3.0`, `typescript 6.0.3`. Каталогу `src/` немає. Аліасів шляхів у `tsconfig.json` немає.

## 3. Ухвалені рішення

### 3.1. Район — дані конфігурації, а не обмеження карти

Прямокутник 50.75/0.95 → 51.25/1.95 живе в конфігурації як значення й у B-02 не впливає на поведінку карти. `maxBounds` не встановлюємо, `fitBounds` не викликаємо: початковий вид задають центр 51.00/1.45 і zoom 10 з тієї ж конфігурації.

Чому: US-01 вимагає, щоб карту можна було рухати й наближати, а п.7 брифу прямо описує ситуацію «викладач випадково зсунув карту» як допустиму. Обмеження району суперечило б обом. Прямокутник знадобиться в B-05 (точки маршрутів усередині району) і в R2 (bbox запиту) — до того часу це експортована константа без споживача, і так і записано в огляді diff.

Наслідок, який приймаємо свідомо: у B-02 район присутній у конфігурації, але не доведений жодною перевіркою. Доведе його B-05.

### 3.2. Розкладка файлів — FSD у `src/`, з префіксом `_` для шарів

Обрано канонічну розкладку Feature-Sliced Design у `src/`, а не пласку колокацію біля маршруту.

Важлива поправка до початкового формулювання: шари називаються `src/_pages/` і `src/_app/` — **з підкресленням**. Причина технічна, не стилістична: Next.js вважає `src/pages/` каталогом Pages Router, тому `src/pages/home/ui/leaflet-map.tsx` потрапив би в маршрутизацію й може ламати збірку на Next 13.5+. Це та сама поправка, яку дає офіційний гайд FSD для Next.js; Steiger також очікує саме такі імена.

`app/` у корені лишається суто маршрутизацією: файл маршруту не містить логіки, лише реекспорт.

### 3.3. Клієнтське підключення Leaflet — два шари захисту

Leaflet звертається до `document` під час обчислення модуля, тому будь-який статичний імпорт у модулі, який рендериться на сервері, ламає `next build`. Захист:

- `leaflet-map.tsx` — `'use client'`, статичні імпорти `leaflet` і `leaflet/dist/leaflet.css`, уся робота з картою;
- `dover-strait-map.tsx` — `'use client'`, єдиний шлях до попереднього модуля: `dynamic(() => import('./leaflet-map'), { ssr: false })`.

Посередник потрібен саме тому, що `ssr: false` заборонений у серверних компонентах (`docs/context/How to lazy load Client Components and libraries.md:97`). Серверний компонент сторінки рендерить `<DoverStraitMap/>`; модуль Leaflet на сервері не обчислюється взагалі.

Обгортку `react-leaflet` не додаємо — це зайва залежність, а сам Leaflet у цьому обсязі це десяток рядків.

### 3.4. Ініціалізація синхронна, прибирання явне

Карта створюється синхронно в `useEffect` (не `await import()` усередині ефекту), cleanup викликає `map.remove()`.

Чому: у React StrictMode ефект виконується двічі. Синхронна пара «створити / `remove()`» коректна за побудовою. Асинхронна ініціалізація потребувала б прапорця скасування, інакше другий прохід падає на «Map container is already initialized». Та сама дисципліна знадобиться в B-06 для таймерів.

### 3.5. Розмір і перемальовування

Ланцюжок висоти: `html, body { height: 100% }` → `.page { display: flex; height: 100% }` → `.map { flex: 1 }`. Плюс `body { margin: 0 }`, інакше типовий відступ дає смуги прокручування.

Де живуть ці класи: скидання документа — у глобальному файлі шару `_app` (єдиний глобальний стиль у проєкті), а `.page` і `.map` — у CSS-модулях поруч зі своїми компонентами, за володінням: розкладку сторінки описує сторінка, розмір карти — карта.

Перемальовування при зміні вікна забезпечує власна опція Leaflet `trackResize` (увімкнена за замовчуванням): Leaflet слухає `resize` вікна й сам викликає `invalidateSize`. `ResizeObserver` не додаємо. Якщо візуальна перевірка покаже артефакти — повертаємося до цього пункту явно, а не додаємо спостерігача «про всяк випадок».

Друга класична причина сірого прямокутника — не підключений `leaflet.css`. Він імпортується в тому самому клієнтському модулі, що й бібліотека.

## 4. Архітектура

```
app/layout.tsx                          імпортує глобальні стилі
app/page.tsx                            export { HomePage as default } from '@/_pages/home'
src/_app/styles/globals.css             скидання: висота документа, margin
src/shared/config/map.ts                район, початковий вид, шар тайлів
src/shared/config/index.ts              публічний API сегмента
src/_pages/home/index.ts                публічний API зрізу
src/_pages/home/ui/home-page.tsx        серверний компонент, розкладка сторінки
src/_pages/home/ui/home-page.module.css .page
src/_pages/home/ui/dover-strait-map.tsx 'use client', dynamic ssr:false
src/_pages/home/ui/leaflet-map.tsx      'use client', Leaflet
src/_pages/home/ui/leaflet-map.module.css .map
```

Потік даних односторонній і тривіальний: `shared/config` → `leaflet-map` → Leaflet. Жодного стану, жодних пропсів, жодних подій. Стан суден з'явиться в B-03 і вище.

Межі модулів:

- `shared/config/map.ts` — знає значення району, виду й тайлів; не знає про Leaflet і React;
- `leaflet-map.tsx` — знає Leaflet і DOM; не знає про маршрутизацію Next;
- `dover-strait-map.tsx` — знає одне: що карту не можна рендерити на сервері;
- `home-page.tsx` — знає, як розкладена сторінка.

`maxZoom` не задаємо: у завданні його немає, а типове значення Leaflet не створює запитів до неіснуючих тайлів.

### Аліаси шляхів

У `tsconfig.json` додаються `baseUrl: "."` і `paths` рівно на три шари, які справді існують: `@/_app/*`, `@/_pages/*`, `@/shared/*`. Next.js читає їх сам, зміни в `next.config.ts` не потрібні.

## 5. Залежності

- `leaflet@1.9.4` — залежність, зафіксована завданням (1.9.x);
- `@types/leaflet@1.9.22` — devDependency.

Типи потрібні: перевірено `npm view leaflet@1.9.4 types` — поля немає, пакет не постачає декларацій, а проєкт на `strict`. Це не «зайва залежність» у сенсі меж спринту, а спосіб користуватися вже дозволеною бібліотекою з TypeScript. Версії фіксуються точно, без `^`, як це зробив B-01.

Більше не додається нічого: ні `react-leaflet`, ні `geodesy`, ні тестових фреймворків.

## 6. Помилкові стани

Свідомо не обробляються, і це рішення, а не забудькуватість:

- **тайли не завантажилися (немає мережі)** — Leaflet показує порожню сітку, атрибуція лишається. Бриф п.7 прямо каже, що для карти потрібен інтернет і автономна робота карти не потрібна. Свого повідомлення не малюємо;
- **`containerRef.current === null`** — ефект виходить без дії; гілка існує лише щоб задовольнити `strict`, не як сценарій;
- повідомлень про помилки, спінерів і `loading`-заглушки для `dynamic` не додаємо: карта займає всю область, підміна нічим не зменшує зсув розкладки.

## 7. Як перевіряємо

Автоматичних тестів цього тижня тут немає — Playwright приходить у B-07, і в записі checkpoint це фіксується як факт.

| Критерій | Чим доводиться |
| --- | --- |
| `next build` проходить | `npm run build` — машинна перевірка, вона ж доказ, що Leaflet не потрапив на сервер |
| Пряме відкриття й оновлення | Браузер: відкрити `http://127.0.0.1:3000`, потім оновити; карта й тайли на місці, консоль чиста |
| Зміна розміру без артефактів | Браузер: щонайменше два розміри вікна; без сірих смуг і зміщення тайлів |
| Атрибуція (US-01) | Очима: «© OpenStreetMap contributors» у кутку карти |
| Карта рухається й наближається (US-01) | Очима: перетягування й зум |
| Район і вид із конфігурації | Читанням diff: єдине місце значень — `shared/config/map.ts` |

Перед командами — `nvm use` (у `.nvmrc` Node 24; в оболонці зараз 22). `node_modules` у цій робочій копії порожній, тому першим кроком іде `npm install`.

## 8. Поза межами B-02

Судна, значки, картка, панель, підпис джерела, кнопка, будь-який стан, `metadata`/заголовок вкладки, тести, `maxBounds`, `maxZoom`, `ResizeObserver`, обгортки над Leaflet, заготовки під справжні дані. Плейсхолдерний текст із B-01 у `app/page.tsx` прибирається — його місце займає карта.

## 9. Ризики

- **Хвіст StrictMode.** Якщо cleanup зникне при майбутньому редагуванні, помилка «Map container is already initialized» з'явиться лише в dev і лише після другого рендера. Тому `map.remove()` — не деталь, а пункт огляду diff.
- **Плаский `app/` → `src/` з шарами.** Розкладка змінюється на другому завданні спринту; далі B-03…B-06 додають зрізи в уже наявні шари, нових каталогів «на майбутнє» не створюємо.
